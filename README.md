# 112 AI Trainer

В однокарточном занятии кнопка «Начать карточку заново» доступна в верхней
учебной полосе прямо во время работы с АРМ. В журнале она подписана «Начать
занятие заново». Предыдущая попытка и оценка сохраняются.

При смене учебной группы старые карточки остаются в истории, но больше не
мешают автоматическому появлению новых телефонных докладов в текущем занятии.

В сценариях с режимом «только голос» телефонный доклад нужно прослушать:
карточка не показывает его текст, источник или время, а напоминает лишь
выбрать статус и записать услышанное в комментарий. В текстовом режиме
доклад по-прежнему отображается в карточке.

В конце телефонного доклада поле «Кто подтвердил получение» подставляет
должность собеседника. Если он не назвал фамилию, должности достаточно;
если назвал имя, ученик может уточнить запись вручную.

Повторный звонок начальнику после новой вводной проверяет ход и результат работ;
первичный адрес и тип происшествия повторно называть не нужно. На вопрос бригаде
о времени прибытия сообщается только подтверждённый срок, а при его отсутствии —
что срок пока неизвестен.

Подсказки готовятся в редакторе сценария: «Подготовить черновик подсказок» →
проверить тексты шагов → «Сохранить и утвердить подсказки». Только после этого
можно выдавать практику с подсказками. Изменение сценария снимает утверждение;
выданные карточки сохраняют свою версию. Будущие доклады в подсказках не раскрываются.

Преподаватель разрешает «Практику с подсказками» при выдаче задания/занятия;
по умолчанию подсказки выключены. Для повтора одной карточки ученик открывает
«Реагирование» или «Отчёт и история» → «Начать эту карточку заново».
Старая попытка и диалог сохраняются, преподаватель видит номер и отметку повтора.

Карта переведена на MapLibre с локальным векторным архивом Москвы и области.
Тайлы, подписи, шрифты и значки загружаются с сервера тренажёра, без внешнего API.
Подготовка подложки и адресного поиска описана в [docs/MAPS.md](docs/MAPS.md).

На карте кнопка «Указать на карте» позволяет выбрать точку щелчком и скопировать
её координаты WGS84. Перетаскивание перемещает карту без изменения выбранной точки.
В режиме 112 координаты можно перенести в черновик с подтверждением; в ДДС —
скопировать для комментария, не изменяя исходные данные карточки.

В сценарии можно отключить текстовое общение (`text_input_allowed`), не блокируя
заполнение карточки и комментариев. Для такого занятия преподаватель назначает
участникам SIP-номера; кнопка «Настроить IP-телефоны» доступна и у уже созданного
занятия, пока телефонные разговоры не начаты. Отчёты показывают фактически
использованный канал и число реплик. Вводное упражнение использует IP-телефон.
Доклады назначенной бригады начинаются после завершённой передачи задачи,
а не после выбора бригады или открытия окна доклада.

## Что это

Тренажёр воспроизводит рабочее место диспетчера дежурно-диспетчерской службы (ДДС), которое получает карточки происшествий от Системы-112 города Москвы. Интерфейс карточки и реестра обращений повторяет АРМ ДДС. Всё работает в изолированном контуре: сервер, языковые модели, распознавание и синтез речи, телефония и карта — локальные.

**Что отрабатывает обучаемый:**

| Действие | Что проверяется |
| --- | --- |
| Открыть поступившую карточку | не позже 30 секунд от появления в строке сообщений |
| Принять карточку или мотивированно не принять | первая запись (статус и текст) не позже 3 минут |
| Назначить бригаду своей службы | бригада выбрана до выезда, решение руководителя при необходимости |
| Доложить по телефону | адрес, тип происшествия и существенные факты названы полностью |
| Отразить каждый доклад бригады | статусы по порядку, у каждого — комментарий со сведениями с места |
| Заметить ошибку в карточке 112 | правильное значение передано в Службу 112 |
| Закрыть работу | результат записан, все статусы цикла пройдены, карточка отработана |

Цикл статусов своей службы: Добавлена → Получена службой → Принята / Не принята → Начало реагирования → Прибытие → Проведение работ → Работы завершены / Отказ от выполнения работ.

**Голос.** Диспетчер разговаривает по учебному IP-телефону (MicroSIP или аппаратный SIP-телефон) с вышестоящим начальником и с руководителем бригады. Бригада сама звонит с докладами о ходе работ, на вопросы отвечает локальная языковая модель, опираясь только на факты сценария. Дополнительно есть режим полного цикла 112 — приём вызова от заявителя с голосом.

**ИИ.** Генерация сценариев и эталонов по теме занятия с корректировкой комментарием преподавателя; голос бригады и начальника смены; разбор ошибок ученика и типичных ошибок группы. Поправки преподавателя сохраняются и учитываются в следующих ответах модели. Действия и сроки проверяются по журналу событий. Свободные формулировки дополнительно сверяются локальной моделью; смысловой зачёт отмечается в отчёте для преподавателя.

**Доклад по телефону.** Проверка доклада помнит все факты разговора и сама задаёт обязательные уточнения; ИИ отвечает на свободные вопросы. Если тип происшествия назван своими словами («из трубы хлещет вода»), локальная модель сверяет смысл и засчитывает его только с дословной цитатой ученика. Город, улицу и объект, названные не дословно или искажённые распознаванием речи («дпо около станции пассажирско киетская»), модель сравнивает с карточкой и отвечает «то же место / только общее слово / другое место»; засчитывается только «то же место» с цитатой из речи, в которой есть опознавательное слово. Если модель недоступна, названия мест сравниваются приблизительно (2/3 значимых слов) с пометкой для преподавателя. Номера сверяются строго. Разные номера дома требуют явного уточнения («уточняю, дом 12»).

**Роли.** Администратор — пользователи, сервисы, конфигурация, резервные копии, журналы. Преподаватель — сценарии, группы, занятия, наблюдение в реальном времени, отчёты, экспертная оценка, аналитика. Обучающийся — назначенные занятия, рабочее место, справочные материалы, свои результаты. Профиль ДДС в занятии ограничивает ленту обучающегося событиями своей службы.

**Время на карточке.** Общее время идёт от поступления карточки, как в АРМ-112; под ним виден текущий норматив: «осталось 0:12» → жёлтый у предела → «просрочено +0:08». Норматив реакции и порог зачёта задаются в занятии (по умолчанию 30 с). Попытка без действий обучающегося дольше `CARD_ABANDON_MINUTES` (120 мин) закрывается системой, время считается до последнего действия.

**Сквозной разбор попытки.** Страница `/review` показывает маршрут «задание → карточка → звонок → решение → разбор»: условия, нормативы с фактом, хронологию с отметкой «+мм:сс» от поступления карточки, расшифровки и записи всех звонков, карточку против эталона и итог оценки. Открывается из кабинета, статистики и отчёта рабочего места.

**Прогноз готовности и графики.** Для каждого обучающегося — прогноз балла следующей попытки с интервалом и объяснением (метод Хольта). Достоверность проверяется скользящим прогнозом на попытках стенда против простых способов «последний балл» и «средний балл» и на описанной синтетической когорте. Порог готовности настраивается. Под каждым графиком указан источник (попытки, период, откуда балл), таблица значений и выгрузка CSV.

**Телефон в браузере (WebRTC).** Вместо MicroSIP или вместе с ним ученик нажимает «телефон в браузере» на рабочем месте. Браузер регистрируется в Asterisk через тот же защищённый адрес сайта, и учебные звонки на его номер приходят прямо в браузер: сигнал вызова, «Ответить» / «Отклонить», выбор гарнитуры, индикатор микрофона. Во время разговора видны задержка, джиттер и потери пакетов. Номер 100 — эхо-тест гарнитуры. Если браузер не подключён, звонок идёт на IP-телефон, как раньше.

**Записи звонков.** Каждый звонок пишется в WAV без потерь и в компактный MP3. В сквозном разборе запись прослушивается, оба формата можно скачать.

**Двухфакторный вход.** Код из любого приложения-аутентификатора (TOTP: Яндекс Ключ, Google/Microsoft Authenticator, FreeOTP) после пароля, резервные коды, сброс администратором; администратор может сделать второй фактор обязательным для ролей. Работает без интернета.

## Архитектура

| Компонент | Технологии | Порт |
| --- | --- | --- |
| Frontend | статический веб-интерфейс, FastAPI-прокси с проверкой сессии | 3000 |
| Backend | Python 3.12, FastAPI, PostgreSQL (SQLite для разработки) | 8000 |
| Voice | FastAPI, Asterisk ARI, Vosk + GigaAM v2 (распознавание), Silero v5.5 (синтез) | 8001 |
| Телефония | Asterisk 22, SIP TLS 5061, SRTP | 5061 |
| Модели | Ollama: `qwen3:4b-instruct` для телефона, `qwen3:8b` для авторинга | 11434 |
| Инфраструктура | Docker Compose, HAProxy (две реплики Backend), LDAPS-каталог, шифрованные резервные копии | — |

REST — `/api/v1`, события — WebSocket `/ws/v1`. Контракты: [docs/API_CONTRACT.md](docs/API_CONTRACT.md), [shared/api/openapi.yaml](shared/api/openapi.yaml), [shared/api/asyncapi.yaml](shared/api/asyncapi.yaml). Подробная схема — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

**CPU или GPU.** Языковая модель работает на процессоре минимального сервера или на видеокарте: параметр `LLM_DEVICE` (`auto`, `cpu`, `gpu`) задаётся в `.env.docker` или в кабинете администратора. Замеры: ответ модели на видеокарте 0,4 с, на процессоре около 2 с; типовые ходы доклада обрабатываются правилами за 0,2 с. Подробнее — [docs/LOCAL_MODEL.md](docs/LOCAL_MODEL.md).

## Запуск

Нужны Docker (Desktop или Engine + Compose) и Python 3.11+.

```bash
git clone https://github.com/kolloko2/112-ai-trainer.git
cd 112-ai-trainer
git checkout v1.0

python deploy/prepare.py          # приватный .env.docker со случайными паролями
python deploy/manage.py build
python deploy/manage.py up --plain  # http://127.0.0.1:3000
```

Профиль с TLS, кластером и каталогом LDAPS: `python deploy/manage.py up --tls --cluster --directory` (сайт `https://127.0.0.1:3000`). Речевые модели, языковые модели и карта подтягиваются скриптами `tools/fetch_models.py`, `tools/fetch_llm.py`, `tools/prepare_regional_map.py --download`; без них стенд работает на детерминированных ответах.

Первый вход создаёт администратора, затем демонстрационные данные:

```bash
python tools/seed_demo.py --base-url http://127.0.0.1:3000 --admin <логин> --admin-password <пароль>
```

Скрипт создаёт демонстрационные записи преподавателя и обучающихся, группу, сценарии из учебных билетов и занятия, включая обучающее занятие с подсказками. Перед публикацией стенда администратор назначает каждой записи уникальный пароль и выдаёт его лично. Полная инструкция с настройкой телефона — [docs/БЫСТРЫЙ-ЗАПУСК.md](docs/БЫСТРЫЙ-ЗАПУСК.md), установка на сервер — руководство сервера в [комплекте документации](output/documentation-2026-09-28/).

## Структура репозитория

| Каталог | Содержимое |
| --- | --- |
| `backend/` | API, рабочее место, занятия, оценка, генерация, доклады, аналитика |
| `frontend/` | АРМ ДДС, кабинеты преподавателя и администратора, карта |
| `voice/` | голосовой шлюз: Asterisk ARI, распознавание, синтез, запись |
| `deploy/` | Docker Compose, TLS, кластер, Asterisk, резервное копирование, эксплуатация |
| `shared/api/` | OpenAPI и AsyncAPI |
| `tools/` | загрузка моделей, импорт билетов и классификатора, демо-данные, приёмочные проверки |
| `docs/` | архитектура, API, эксплуатация, модель, речь, безопасность |
| `output/` | комплект документации и презентация |

Учебные данные синтетические: реальные данные Системы-112 не используются, внешние сети в работе тренажёра не задействованы.
