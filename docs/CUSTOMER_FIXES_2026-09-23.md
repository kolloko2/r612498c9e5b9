# Доведение по результатам сверки с заказчиком

Изменения относятся к пунктам 1–5 аудита. Испытание PostgreSQL на этом компьютере
не повторялось: заказчик проекта перенёс приёмку производительности на более
мощное оборудование. Голосовые измерения приведены отдельно в VOICE_CHECK_2026-09-23.md.

## Доклад и оценка

Доклад больше не принимается по случайному слову «квартира» вместо «пожар».
Локальная морфология учитывает формы русских слов; проверка отрицаний отклоняет
«пожар не подтверждён», «пожара нет», противоречащие друг другу утверждения.
Корпус, строение, квартира и наличие пострадавших при заполненных полях входят
в стандартную проверку. Номер квартиры нельзя выдать за номер корпуса.

Преподаватель может задать `brief_required_fields`, веса `check_weights` и
`pass_percent` в эталоне ДДС. Критические ошибки по-прежнему блокируют успешную
оценку. Пустой список обязательных полей использует стандартный набор.
Старые завершённые отчёты не пересчитываются.

Для публикации сценария с `expected_corrections` теперь нужна
`correction_evidence` для каждого исправляемого поля. Эта вводная показывается
ученику в рабочем месте; скрытый эталон не заменяет источник сведений.
Черновик можно сохранить до подготовки вводных. У ранее выданных упражнений
не меняются снимки требований.

Проверка текста дополнена локальным словарём и проверкой некоторых согласований
прилагательного с существительным. Словарные подсказки отделены от штрафных
ошибок: неизвестное название не объявляется автоматически неграмотным.
Близкое к эталону название улицы отмечается как расхождение, без автоматической
замены адреса. Это ограниченная проверка русского текста, а не полный редактор
синтаксиса или юридически значимая проверка действий диспетчера.

В импорте билетов явная роль звонящего («вызывает брат», «вызывает мама») теперь
имеет приоритет перед первым ФИО пострадавшего. Каталог 96 черновиков пересобран.
Изменённые преподавателем опубликованные сценарии не перезаписывались; их
методическая приёмка остаётся задачей преподавателя.

## Материалы

- PDF, TXT, DOCX и XLSX до 25 MiB; до 100 материалов и 500 MiB вложений на преподавателя.
- Текст извлекается при сохранении со всех страниц PDF в пределах 200 страниц;
  OCR применяется к страницам без достаточного текстового слоя и к изображениям DOCX.
- Локальный Tesseract использует rus+eng. В Docker-пакет Backend добавлены движок
  и языки; Windows может использовать установленный Tesseract через `TESSERACT_CMD`.
  Допустим также JSON-массив команды, например
  `["wsl","-d","AlmaLinux-9","--exec","tesseract"]`. Shell не используется.
- Бюджет OCR — 180 секунд, извлечённого текста — 1 млн символов; XLSX — до 10000
  строк и 200 столбцов на лист. При достижении границы выводится статус частичной
  обработки и причина. Рисунки неподдерживаемых форматов также не скрываются.
- Извлечённые фрагменты сохраняются вместе с ревизией документа. Поиск учитывает
  текущее упражнение и все опубликованные материалы подходящего преподавателя,
  профиля и группы. В ответ модели передаётся до 12000 символов с именем источника,
  страницей/строкой. Это выбор относящихся к задаче фрагментов, а не обещание
  поместить всю библиотеку в один запрос модели.
- В редакторе видны статус обработки, предупреждения, объём и начало извлечённого
  текста. Ранее загруженные документы нужно пересохранить, чтобы создать индекс;
  автоматически запускать тяжёлый OCR во время голосового разговора система не будет.

Наличие OCR не гарантирует безошибочной расшифровки скана. Преподавателю следует
проверить ключевые адреса, номера и эталоны после распознавания.

## Территории

Исправлено описание полей: `district` — округ, `area` — район. По умолчанию
используется ограниченный учебный справочник `backend/data/territorial_routes.json`
с примером Str1fe №690: Москва, район Щукино → район Щукино и СЗАО;
явно заданный объект «Школа» → Департамент образования. Имена здесь являются
учебными подписями получателей, а не выдуманным официальным реестром подразделений.
При другом районе или неизвестном объекте догадок нет. Автоматической географической
привязки всех московских улиц не добавлено: исходного утверждённого справочника нет.

Для расширения добавлен `tools/import_territories.py`: XLSX с колонками `id`,
`approved`, `source`, адресными полями и `services` (получатели по одному в строке).
Каждая строка сохраняет источник и явную отметку утверждения. Конвертер валидирует
справочник и создаёт новый JSON, не затирая действующий файл. После проверки
администратор задаёт `TERRITORIAL_ROUTES_FILE`. Отдельная БД или сервис не добавлены.

## Таймер

Цветовой индикатор после приёма использует `handling_limit_seconds`, тот же лимит,
который рассчитывает сервер с учётом вводных. Подтверждение приёма остаётся
отдельным учебным лимитом 30 секунд; открытие строки не приравнивается к приёму.

## Развёртывание

Установить обновлённые `backend/requirements.txt`, пересобрать образ Backend для
OCR, обновить Frontend и Voice. Приватные ENV, действующая БД и Docker-контейнеры
в этой работе не заменялись. Для локального mock-просмотра служит
`python tools/run_workspace.py --review-db <отдельная.sqlite>`.

В голосовых дочерних процессах включён UTF-8. Загрузка моделей исправлена для
Windows-каталогов с кириллицей: Python открывает/выбирает каталог модели, а native
библиотека получает локальное имя. Модели не копируются и не скачиваются при звонке.

проверок весов, отрицания результата и XLSX-импорта территорий целевой набор:
13 passed. Voice: 51 passed. JavaScript прошёл синтаксическую проверку.
В браузере проверены сохранение методички, статус извлечения, предпросмотр и
появление новых настроек сценария. OCR на исходном сканированном документе
обработал 32 страницы за 58,05 секунды, извлёк 22 939 символов; это проверка
обработки всех страниц, не подтверждение безошибочного распознавания каждого слова.
