Название: Руководство по развёртыванию и эксплуатации сервера
Обозначение: Т112 ПД 02
Основание: ГОСТ 19.503-79
Аннотация: Руководство предназначено для системного администратора. Описывает установку нового локального стенда, адресацию, подготовку моделей и сертификатов, запуск сервисов, резервное копирование, обновление и диагностику. Рабочие данные существующего стенда не требуется пересоздавать.

## Общие сведения о программе

Сервер обслуживает веб-интерфейс, учебные сессии, телефонные диалоги и хранение результатов. Все модели работают локально. Видеокарта не обязательна: без неё языковая модель работает на CPU, с ней — ускоряется автоматически (LLM_DEVICE=auto). Облачные ключи не нужны. Ученикам не нужно устанавливать Docker, Python или Ollama.

Для ИИ-сервера в ТЗ указаны процессор Intel Core i7 или Xeon либо аналог от шести ядер, RAM от 32 ГБ и NVMe SSD от 512 ГБ. Фактический объём свободного места рассчитывают с учётом образов, моделей, карты, записей и резервных копий. Оставьте свободное место для записей и резервных копий.

Поддерживаемая схема установки: Linux с Docker Engine и Compose либо Windows с Docker Desktop в режиме Linux-контейнеров. Нужны Git, Python версии 3.12 или выше, OpenSSL и Ollama. Compose должен поддерживать !override, то есть версию не ниже 2.24.4. Команды ниже выполняются из корня репозитория. На Linux команда python при необходимости заменяется на python3.

## Структура программы и сетевые связи

Frontend принимает HTTPS-запросы на порту 3000 и передаёт их Backend. Backend обращается к базе и локальному Ollama. Voice связывает Asterisk с распознаванием, моделью и синтезом. Служебные порты не публикуются для учеников.

| Направление | Протокол и порт | Назначение |
| --- | --- | --- |
| ПК ученика → сервер | HTTPS TCP 3000 | Сайт |
| IP-телефон → сервер | SIP TLS TCP 5061 | Регистрация и управление звонком |
| Телефон ↔ сервер | SRTP UDP 20000–20199 на сервере | Звуковой поток |
| Контейнеры → Ollama | HTTP TCP 11434 в доверенном сегменте | Локальный инференс |
| Backend ↔ база | TLS TCP 5432 внутри Compose | Учебные данные |
| Сервисные соединения | HTTPS 8000 и 8001, ARI 8089 | Внутреннее взаимодействие |

Ollama не имеет публичного пользовательского входа в этой схеме. Его порт разрешают только серверным компонентам, не всей ученической сети. Для удалённого узла моделей требуется отдельная защищённая транспортная конфигурация: текущий адаптер обычно обращается по HTTP внутри доверенной среды.

## Подготовка адреса сервера

Назначьте серверу постоянный IP. Далее во всех примерах используется 192.168.10.10, имя trainer112.lan, подсеть рабочих мест 192.168.10.0/24. Это пример: до выполнения команд замените его своим адресом. Одинаковые фактические значения должны попасть в сертификаты, переменные среды, правила межсетевого экрана и карточку подключения ученика.

Если локального DNS нет, используйте IP во всех настройках. В этом случае адрес сайта имеет вид https://192.168.10.10:3000. Адрес 127.0.0.1 на компьютере ученика обозначает сам компьютер ученика, а не сервер.

Разрешите указанные внешние порты только из учебной подсети. Не открывайте наружу PostgreSQL, ARI, Voice и Ollama. Проверьте синхронизацию времени сервера и рабочих мест. Сертификаты с истёкшим сроком или другим именем не следует обходить через предупреждение браузера.

## Получение комплекта и зависимостей

На подготовительной машине с доступом к сети получите исходники и зафиксируйте нужную версию. Для приватного репозитория нужен доступ, выданный владельцем.

```text
git clone https://github.com/kolloko2/112-ai-trainer.git
cd 112-ai-trainer
git checkout 9fb10f8
python -m venv .venv
```

Активируйте среду: Windows — .venv\Scripts\Activate.ps1; Linux — source .venv/bin/activate. Установите зависимости служебных скриптов. Полный список приведён в deploy/requirements.txt; основной код устанавливается внутрь контейнеров при сборке.

```text
python -m pip install -r deploy/requirements.txt
python deploy/prepare.py
```

prepare.py создаёт .env.docker с уникальными секретами и SIP-аккаунтами 201–220, а также ключ резервного копирования. Он не перезаписывает существующий ENV. Не запускайте подготовку заново для смены адреса работающего сервера: изменяйте существующие настройки после резервного копирования.

Сопоставление номера телефона и индивидуального пароля хранится в SIP_ACCOUNTS_JSON внутри .env.docker. Разрешённые номера перечислены в ALLOWED_EXTENSIONS. Администратор выдаёт рабочему месту только его номер и пароль по защищённому каналу, а не весь файл конфигурации. Ведите таблицу «ученик — АРМ — SIP-номер»; преподаватель использует номера из этой таблицы при подготовке занятия.

## Настройка локального ИИ и ресурсов

В защищённом редакторе откройте .env.docker. Для новой поставки задайте следующие несекретные параметры; сгенерированные пароли сохраните без изменений.

```text
LLM_PROVIDER='ollama'
LLM_PROFILE='standard'
OLLAMA_URL='http://host.docker.internal:11434'
PHONE_LLM_MODEL='qwen3:4b-instruct-2507-q4_K_M'
PHONE_LLM_THREADS='6'
OPENROUTER_API_KEY=''
INSTALL_LOCAL_PROVIDERS='true'
INSTALL_SILERO='true'
STT_PROVIDER='hybrid'
STT_MODEL='/models/vosk-model-small-ru-0.22'
STT_FINAL_MODEL='/models/sherpa-onnx-nemo-ctc-giga-am-v2-russian-2025-04-19'
TTS_PROVIDER='silero'
TTS_VOICE='/models/v5_5_ru.pt'
```

Если служебные скрипты запускаются на хосте, локальный Ollama должен быть доступен по адресу хоста; host.docker.internal используется контейнерами. Для загрузки моделей сначала проверьте python tools/fetch_llm.py --help и задайте доступный с хоста URL. Альтернативный прямой способ загрузки:

```text
ollama pull qwen3:8b
ollama pull qwen3:4b-instruct-2507-q4_K_M
python tools/fetch_models.py
python -m pip install "osmium>=4,<5"
python tools/prepare_regional_map.py --download
```

Веса и карта не входят в Git. Для закрытого контура их переносят с подготовительной машины вместе с лицензиями. При старте разговора скачивание из Интернета не требуется. Ollama должен слушать интерфейс, доступный контейнерам; ограничьте доступ межсетевым экраном. На Linux проверьте разрешение host.docker.internal согласно extra_hosts в Compose, а не подставляйте адрес ученического ПК.

Переменная OLLAMA_HOST относится к процессу Ollama на хосте, а не только к .env.docker. Для отдельного запуска на Windows сначала завершите фоновый Ollama, затем в выделенном PowerShell задайте $env:OLLAMA_HOST="0.0.0.0:11434" и выполните ollama serve. На Linux для системной службы задайте Environment="OLLAMA_HOST=0.0.0.0:11434" в её секции Service и перезапустите службу штатными средствами. При таком прослушивании межсетевой экран обязан запрещать доступ к 11434 от ученических и внешних узлов; доступ оставляют только контейнерам сервера. После перезагрузки настройка должна сохраняться в конфигурации службы.

## Настройка HTTPS и SIP

Задайте в .env.docker:

```text
WEB_BIND_ADDRESS='192.168.10.10'
SIP_BIND_ADDRESS='192.168.10.10'
SIP_EXTERNAL_ADDRESS='192.168.10.10'
TLS_ALLOWED_ORIGINS='https://192.168.10.10:3000,https://trainer112.lan:3000'
SIP_LOCAL_NET='172.16.0.0/12'
```

SIP_LOCAL_NET задаёт сети контейнеров для принятия решений NAT. Уточните диапазон фактической Docker-сети; не добавляйте туда автоматически ученическую подсеть. SIP_EXTERNAL_ADDRESS должен быть доступным телефону адресом сервера.

Для нового контура выпустите сертификаты с фактическими DNS и IP. OpenSSL должен быть доступен в PATH.

```text
python deploy/tls/generate.py --dns-san trainer112.lan --ip-san 192.168.10.10
python deploy/tls/validate_overlay.py
```

Генератор отказывается заменять существующие ключи и сертификаты. При смене адреса действующего стенда подготовьте новый комплект отдельно и запланируйте замену; не удаляйте текущий CA ради быстрого запуска. На ПК учеников передают только deploy/tls/ca/ca.cert.pem и проверяют его отпечаток. Закрытый ключ CA на рабочие места не передают.

## Сборка и первый запуск

```text
python deploy/manage.py --tls build
python deploy/manage.py --tls up
python deploy/manage.py status
```

При первом запуске оставьте PIPELINE_MODE='spike' и TOPOLOGY_VERIFIED='false'. Подключите отдельный проверочный телефон, подтвердите регистрацию и двустороннюю передачу звука. Проверку выполняют на свободном учебном номере, не вытесняя телефон ученика. Порядок медиа-пробы описан в voice/README.md.

После проверки установленных моделей и медиа-тракта задайте PIPELINE_MODE='conversation' и TOPOLOGY_VERIFIED='true', затем повторите python deploy/manage.py --tls up.

Откройте https://192.168.10.10:3000/login. В пустой базе форма первоначальной настройки позволяет создать администратора. Придумайте уникальный пароль; затем создайте учётные записи преподавателей и учеников. В существующей базе используйте действующего администратора: повторная начальная настройка не нужна.

## Проверка программы

Проверьте здоровье контейнеров, наличие моделей и регистрацию телефона:

```text
python deploy/check_bundle.py
ollama ps
docker compose --env-file .env.docker exec asterisk asterisk -rx "pjsip show contacts"
```

Устройство телефонной модели задаётся LLM_DEVICE (auto, cpu, gpu) или в кабинете администратора; ollama ps показывает фактическое размещение (CPU или GPU). При смене устройства Backend перезапускается и заново загружает модель. Выполните контрольное занятие: преподаватель назначает карточку ДДС, ученик принимает её, вызывает дежурного через сайт, получает звонок на телефон, передаёт сведения и завершает реагирование. Проверьте сохранение отчёта после повторного входа.

Проверьте карту по адресу внутри установленного региона. Затем отключите внешний доступ в Интернет и повторите вход, карту и короткий диалог.

## Резервное копирование и восстановление

В TLS-профиле запускается backup-worker. Ежедневное расписание задаётся в техническом кабинете администратора; час хранится в UTC. Резервирование работает в Docker и не зависит от планировщика Windows. Копии .t112 шифруются AES-256-GCM. Ключ хранится отдельно в deploy/private/backup.env. Утрата ключа делает архивы недоступными.

Сохраняйте копии и ключ раздельно вне сервера. Модели и региональную карту храните как отдельные поставочные ресурсы: ежедневная копия их не включает. Наблюдайте за свободным местом — автоматическое удаление всех старых копий не предполагается.

Восстановление выполняют на изолированном пустом стенде, а не поверх работающей базы. Сначала сверяют архив и ключ, расшифровывают в отдельный защищённый каталог, читают манифест, восстанавливают дамп и файловые тома согласованной версии. Команда расшифровки:

```text
python deploy/full_backup.py decrypt --source /backup/copy.t112 --output /restore/copy.tar.gz
```

Путь и расширение результата сверяйте с --help и составом архива. Затем штатным pg_restore загружают дамп в пустую базу с правильным владельцем и восстанавливают записи и outbox. До переключения пользователей проверяют вход, карточку, отчёт и доступность записей.

## Обновление и остановка

До обновления завершите занятия, сохраните резервную копию, текущий коммит и образы. Получите новую версию, ознакомьтесь с изменениями конфигурации, пересоберите только необходимые образы и запустите прежний профиль. Не заменяйте рабочий ENV файлом из чужого стенда.

```text
python deploy/manage.py stop
python deploy/manage.py --tls build
python deploy/manage.py --tls up
```

Команда stop сохраняет тома. Не используйте docker compose down -v при обычном обновлении: этот параметр удаляет постоянные тома. При неудаче откатите приложение на сохранённые образы; совместимость схемы данных проверяется отдельно.

Для переноса подготовленного комплекта выполните python deploy/manage.py export-images и загрузите архив на целевой машине командой docker image load -i <архив>. Отдельно перенесите код, deploy/models, deploy/maps и организуйте собственные секреты и сертификаты целевого контура.

## Дополнительные возможности

Для мониторинга хоста и разрешённых операций Voice/Asterisk запускается python deploy/ops_worker.py. На Linux его оформляют службой systemd с рабочим каталогом репозитория. Доступ к Docker является привилегированным; служебная учётная запись не должна использоваться учениками. Резервные копии продолжают обслуживаться контейнером backup-worker.

Профиль --cluster добавляет балансировщик и две реплики Backend с координацией через PostgreSQL. Профиль масштабирует прикладной сервер; голосовые модели и БД обслуживаются отдельно. Подключение каталога LDAPS описано в docs/DIRECTORY_AUTH.md. Локальные роли назначаются администратором.

## Сообщения системному программисту

| Признак | Проверка и действие |
| --- | --- |
| Deployment ENV already exists | Используйте существующую конфигурацию; не удаляйте её |
| Missing key или certificate | Выполните подготовку ключа и сертификатов нового стенда |
| Браузер не доверяет сайту | Сверьте имя SAN, срок и доверие публичному CA |
| Телефон не зарегистрирован | Сверьте TLS 5061, номер, пароль, сервер и правила сети |
| Есть звонок, нет звука | Сверьте SRTP, RTP-диапазон, NAT, гарнитуру и модели |
| ИИ не отвечает | Проверьте Ollama с контейнерной стороны, наличие весов и RAM |
| Карта недоступна | Проверьте deploy/maps/regional.sqlite и права чтения |
| Нет свежей копии | Проверьте backup-worker, расписание UTC, ключ и место на диске |
