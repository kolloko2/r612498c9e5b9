## Общие сведения

Исходный код: https://github.com/kolloko2/112-ai-trainer, версия 9fb10f8. Приложение состоит из Python-сервисов, браузерного интерфейса на JavaScript, локальной АТС и файловых ресурсов. Контейнеры собираются из Dockerfile проекта. Ollama работает на локальном хосте и доступен серверным компонентам.

Устройство языковой модели задаётся параметром LLM_DEVICE: auto (по умолчанию — видеокарта при наличии, иначе CPU), cpu (num_gpu=0, минимальный сервер по ТЗ) или gpu (все слои на видеокарте). Речевые модели исполняются локальными CPU-провайдерами. Для использования продукта не нужны API-ключи сторонних поставщиков ИИ. Сохранённый в исходниках адаптер OpenRouter является альтернативной ветвью разработки и выключен в описанной конфигурации.

## Функциональная архитектура

Браузер обращается к Frontend по HTTPS. Frontend обслуживает файлы интерфейса и проксирует разрешённые запросы Backend и Voice. Backend проверяет роль и принадлежность данных, хранит версии сценариев, события и оценки. Voice управляет аудиотрактом и соединяется с Asterisk через ARI и WebSocket media.

LLM получает роль собеседника, текущие доступные факты и ограниченную историю. Будущие доклады и приватные эталоны не должны попадать в контекст ученика. Изменение статусов и оценка решений выполняются серверными правилами, а не произвольной командой языковой модели.

| Каталог | Ответственность |
| --- | --- |
| backend | Учебная логика, модели данных, оценка, API и доступ |
| frontend | HTML, CSS, JavaScript и сервер интерфейса |
| voice/app | Состояния звонков, аудио, провайдеры речи и обмен событиями |
| deploy | Контейнеры, TLS, резервирование и операции |
| shared/api | Контракты OpenAPI и AsyncAPI |
| tools | Импорт, подготовка ресурсов, демонстрация и проверки |

## Языковые и речевые модели

| Компонент | Рабочий вариант | Назначение |
| --- | --- | --- |
| Телефонный диалог | Qwen3 4B Instruct 2507 Q4_K_M | Короткий ответ собеседника по фактам |
| Авторинг и разбор | qwen3:8b, профиль standard | Сценарии, эталоны и аналитические пояснения |
| Предварительное распознавание | Vosk small ru 0.22 | Локальная обработка русской речи |
| Финальное распознавание | GigaAM v2 CTC через sherpa-onnx, INT8 | Уточнение результата распознавания |
| Синтез | Silero v5_5_ru, голос baya | Русская речь локально на CPU |
| Морфология | pymorphy3 | Локальный анализ словоформ и проверок текста |
| OCR | Tesseract rus и eng | Извлечение текста из изображений документов |

Для телефонной модели установлен контекст 4096 токенов, максимум 120 выходных токенов, температура 0,2 и шесть CPU-потоков на измеренном шестиядерном хосте в режиме CPU. Инструкции ограничивают ответ короткой русской репликой. Модель Instruct не использует длинный режим рассуждений в этом профиле.

Квантование Q4_K_M уменьшает объём весов телефонной LLM; установленный файл занимает примерно 2,5 ГБ, прогретый процесс модели на стенде — около 3,2 ГБ. GigaAM использует отдельный INT8 ONNX-файл. Нельзя переносить эти значения на всю оперативную память комплекса: другие модели, сервисы и буферы требуют собственных ресурсов.

## Инфраструктура и форматы

Используются Docker Compose, PostgreSQL 16, Asterisk 22.11.0, Ollama и OpenSSL. Дополнительный профиль балансировки использует HAProxy; тестовый каталог — OpenLDAP. Каталог организации подключается по его адресу и параметрам LDAPS.

| Интерфейс или формат | Использование |
| --- | --- |
| REST /api/v1 | Аккаунты, задания, карточки, оценка и администрирование |
| WebSocket /ws/v1 | События диалога и взаимодействие с голосом |
| OpenAPI и AsyncAPI | Машиночитаемые контракты |
| JSON | Сценарии, эталоны, события, экспорт и API |
| XML | Импорт и экспорт поддерживаемых настроек и материалов |
| CSV и XLSX | Статистика и табличный обмен |
| PDF и DOCX | Отчёты, сертификаты и методические материалы |
| WAV и аудиозаписи | Учебные разговоры и проверочные записи |
| TLS, WSS, SRTP | Защищённые сетевые соединения профиля |

XML-обмен охватывает определённые схемы приложения. Он не объявляется универсальной совместимостью со всеми внешними форматами Системы-112. CSV/XLSX защищают текстовые значения от интерпретации как формул при выгрузке.

## Хранение и воспроизводимость

Основные данные находятся в PostgreSQL; аудио и служебные очереди — в постоянных томах. Карта использует отдельный SQLite-пакет только как картографический ресурс, не как замену основной БД. Секреты передаются через окружение и не входят в образ или Git.

Для воспроизводимой поставки фиксируют коммит, хеши контейнерных образов, файлы и контрольные суммы моделей и карты, версии зависимостей и конфигурационный профиль. Диапазоны версий в requirements задают допустимые зависимости, а снимок установленной среды фиксирует конкретный стенд.

Лицензии кода, моделей, шрифтов и карты рассматриваются отдельно. При передаче весов необходимо сохранить сопровождающие лицензионные файлы. Каждая модель поставляется со своей лицензией. Для данных OpenStreetMap сохраняется атрибуция источника.

## Дополнительные возможности и развитие

Новые упражнения добавляются через версионную библиотеку. Для новых служб расширяются справочник, классификатор, получатели территории и профиля, а затем проверяются сценарии. Не следует жёстко привязывать алгоритм к одной ДДС.

Телефонная модель меняется через PHONE_LLM_MODEL после проверки роли, фактов и задержек. Увеличение контекста повышает стоимость обработки; сначала целесообразно сокращать повторные доклады и несущественную историю. Увеличение числа потоков CPU требует измерения, поскольку STT и TTS используют тот же процессор.

Переключение CPU/GPU выполняется параметром LLM_DEVICE без изменения кода; замеры обоих режимов — в Т112 ПД 08. Расширение количества голосовых узлов требует маршрутизации звонков и состояния Voice; увеличение числа Backend-реплик само по себе не увеличивает пропускную способность модели.
