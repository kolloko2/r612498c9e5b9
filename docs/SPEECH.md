# Распознавание речи: замеры и конфигурация

Текущий синтез использует пул Silero и кэш, настройки/замер 26 сентября —
[CURRENT_RUNBOOK](CURRENT_RUNBOOK.md). Приведённый ниже STT-замер исторический;
это не подтверждение одновременной нагрузки STT/TTS/LLM.

Дата измерения: 16 сентября 2026 года. Хост: AMD Ryzen 5 5600 (6 ядер), CPU-режим,
без видеокарты.

## Что было не так

Стенд распознавал речь заметно хуже ожидаемого. Причина оказалась
конфигурационной, а не алгоритмической: в `.env.docker` стояло
`STT_PROVIDER=vosk` с моделью `vosk-model-small-ru-0.22` (88 МБ), а
`STT_FINAL_MODEL` не был задан вовсе. То есть и промежуточный, и финальный текст
выдавала самая слабая из русских моделей Vosk, хотя код проекта с самого начала
поддерживает двухступенчатый режим `hybrid` (быстрые промежуточные результаты
Vosk плюс точное финальное распознавание через sherpa-onnx).

## Замер

`tools/stt_benchmark.py` синтезирует набор из семи фраз системным голосом Windows
(Microsoft Irina, ru-RU) и считает WER — долю слов, которые нужно вставить,
удалить или заменить, чтобы получить эталон. Регистр, пунктуация и ё/е не
учитываются. Набор состоит из того, что диспетчер реально произносит: адрес с
названием улицы, ФИО заявителя, тип происшествия, ответ дежурного службы.

| Модель | Размер | WER | RTF |
| --- | ---: | ---: | ---: |
| vosk-model-small-ru-0.22 | 88 МБ | **19,1 %** | 0,24 |
| sherpa-onnx GigaAM v2 CTC (int8) | 236 МБ | **4,3 %** | 0,13 |

Точная модель не только втрое точнее, но и быстрее: 4,5 секунды на 34,5 секунды
речи против 8,2 секунды. RTF 0,13 означает семикратный запас по скорости на CPU
без видеокарты.

Решающее отличие — адреса. Малая модель распознала «Улица Дубнинская» как «улица
дубне нская», а «Зеленоград, корпус девятьсот два» как «зеленоград корпус
девятьсот два подъезда один». Точная модель обе фразы передала дословно.
Это ровно тот класс ошибок, который постановщик задачи назвал критическим:
расхождение в одну букву в названии улицы уводит силы по другому адресу.

Единственная оставшаяся ошибка точной модели — падежные окончания в фразе
«докладываю по карточке происшествия, пожар в квартире». На заполнение карточки
это не влияет.

Воспроизведение:

```powershell
python tools/stt_benchmark.py --synthesize `
  --vosk deploy/models/vosk-model-small-ru-0.22 `
  --sherpa deploy/models/sherpa-onnx-nemo-ctc-giga-am-v2-russian-2025-04-19
```

Требуются `vosk`, `sherpa-onnx`, `ffmpeg` и системный голос Microsoft Irina.

## Конфигурация после исправления

```
STT_PROVIDER=hybrid
STT_MODEL=/models/vosk-model-small-ru-0.22
STT_FINAL_MODEL=/models/sherpa-onnx-nemo-ctc-giga-am-v2-russian-2025-04-19
```

Vosk остаётся только для промежуточного текста, который виден оператору во время
речи; в карточку и в оценку идёт финальный результат точной модели. Образ Voice
уже содержит `sherpa-onnx` — он входит в зависимости `local`, поэтому пересборка
не требуется, достаточно нового ENV и смонтированной модели.

Модель загружается отдельно и не хранится в Git (`deploy/models/` в `.gitignore`):

```
curl -L -o gigaam.tar.bz2 https://github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-nemo-ctc-giga-am-v2-russian-2025-04-19.tar.bz2
tar -xjf gigaam.tar.bz2 -C deploy/models
```

## Две ошибки, найденные при проверке

**Рукопожатие с воркером ломалось на Windows.** Дочерний процесс печатает
`READY`, а родительский сравнивал строку с `b"READY\n"`. На Windows `print`
переводит перевод строки в `\r\n`, поэтому сравнение не совпадало и Voice
сообщал, что модель не загрузилась. В Linux-контейнере проблема не проявлялась.
Теперь сравнивается содержимое строки, а не её точные байты.

**Vosk не открывает модель по пути с кириллицей.** Kaldi, на котором построен
Vosk, не работает с не-ASCII путями в Windows, а рабочий каталог проекта
называется по-русски. Внутри контейнера путь `/models/...` состоит из ASCII,
поэтому там всё работает. Сообщение об ошибке теперь называет причину прямо.
Для нативного запуска на Windows добавлен провайдер `STT_PROVIDER=sherpa`: он
использует только точную модель, обходится без Vosk и по точности лучше связки с
малой моделью. Плата — отсутствие промежуточного текста во время речи.

## Границы

Замер сделан на синтезированной студийной речи. Телефонный канал (8 кГц, сжатие,
фоновый шум, перебивания) даёт заметно худший результат для любой модели, и эти
цифры нельзя переносить на реальный вызов. Живая проверка через SIP с человеком у
телефона остаётся отдельной приёмкой и здесь не выполнялась. Сравнение с другими
семействами моделей (Whisper, Vosk 0.42) не проводилось.
