Frontend, два Backend, HAProxy, PostgreSQL, Asterisk, Voice, резервное копирование
и учебный каталог LDAP. Ollama работает как служба хоста. Видеокарта не используется.

Учётные записи, сценарии, результаты и материалы перенесены из базы локального
стенда. Перенесены региональная карта, модели Vosk/GigaAM/Silero и история Voice.
Пароли служб, SIP-номеров и ключ резервного копирования созданы отдельно.

## Вход и телефон

Откройте сайт и войдите под своей существующей учётной записью.
Номер АРМ должен соответствовать назначенному преподавателем рабочему месту.

Для MicroSIP/IP-телефона:

- сервер: `212.22.78.93`, порт `5061`;
- транспорт: TLS, шифрование медиа: обязательное SRTP;
- пользователь и идентификатор авторизации: назначенный номер 201–220;
- пароль: значение этого номера в `SIP_ACCOUNTS_JSON` серверного `.env.docker`;
- кодек: PCMU или PCMA; каждый ученик использует отдельный номер.

Сертификат центра: `deploy/tls/ca/ca.cert.pem`. Установите его в доверенные
корневые сертификаты клиентского ПК и используйте для проверки SIP-сервера.
Закрытые ключи из `deploy/tls/private` ученикам не передаются.

## Сеть

В MakeCloud к подключению 10.0.1.4 добавлен профиль
`Trainer112 HTTPS SIP TLS SRTP`: TCP 443, TCP 5061, UDP 20000–20199.
Сохранены исходящий профиль и SSH. PostgreSQL, Backend, Voice, LDAP и ARI
не опубликованы. Ollama слушает только Docker-мост `172.17.0.1:11434`.

`WEB_BIND_ADDRESS=10.0.1.4`, `WEB_PORT=443` публикуют HTTPS на 443,
сохраняя порт 3000 внутри контейнера. `SIP_EXTERNAL_ADDRESS=212.22.78.93`
задаёт публичный адрес в SIP/SDP. Разрешённый веб-origin — `https://212.22.78.93`.

## Обслуживание

```bash
cd /home/ubuntu/trainer112
sudo .venv/bin/python deploy/manage.py status --tls --directory --cluster
sudo .venv/bin/python deploy/manage.py up --tls --directory --cluster
sudo systemctl status ollama trainer112-operations
```

Контейнеры имеют автоматический перезапуск. Хостовый мониторинг запускается
через `trainer112-operations.service`; ежедневные зашифрованные резервные копии
создаёт контейнер `backup-worker` в 00:00 UTC (03:00 Москвы).
Копии находятся в `deploy/backups`, ключ — в `deploy/private/backup.env`.

Телефонная модель — `qwen3:4b-instruct-2507-q4_K_M`, авторинг — `qwen3:8b`.
Контрольные суммы перенесённых весов проверены. Ollama держит в памяти одну
модель и обрабатывает один запрос одновременно, чтобы укладываться в память
сервера. При переключении авторинга и разговора требуется загрузка другой модели.

## Проверка после переноса

В браузере открыты кабинет преподавателя и каталог 32 билетов / 96 упражнений.
Проверены входы преподавателя, ученика, администратора, поиск адресов и свежий
статус мониторинга. Внешнее SIP TLS-соединение установлено с клиентского ПК.

На сервере пройдено занятие с программным TLS/SRTP-телефоном: исходящий доклад,
четыре доклада бригады, распознавание уточняющих вопросов и воспроизведение ответов,
завершение карточки. Итог — 91,67%: превышено общее время упражнения во время
диагностики переноса, критических ошибок нет. Последний ответ закончился после
тайм-аута проверочного скрипта; его воспроизведение подтверждено журналом, карточка
завершена через штатный API. Записи и итог сохранены в `artifacts/server-sip-retry`.

Звонок с конкретного ученического ПК проверяется после регистрации его телефона;
серверная проверка не подменяет проверку NAT и гарнитуры на этом ПК.

На Linux ключ HAProxy должен быть доступен UID/GID 99 образа
`haproxy:3.0-alpine` с правами 0600. Остальные сервисы получают ключи через
`deploy/tls/run_as_user.py`, который сбрасывает привилегии перед запуском.

Не используйте `docker compose down -v`: это удаляет данные. При переносе
истории Voice восстанавливайте её до старта Voice либо остановите его на время
восстановления; открытые SQLite-файлы нельзя заменять под работающим процессом.

Для повторной SIP-проверки адрес сайта задаётся переменной:

```bash
sudo DDS_ACCEPTANCE_BASE_URL=https://212.22.78.93 \
  DDS_ACCEPTANCE_OUT=/home/ubuntu/trainer112/artifacts/server-sip \
  .venv/bin/python tools/acceptance_dds_sip.py --followups
```

Проверка создаёт отдельное занятие и использует тестовый номер 220;
не запускайте её, пока номер занят учеником.
