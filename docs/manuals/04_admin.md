## Из чего состоит тренажёр {#about}

Тренажёр работает на одном сервере в локальной сети учебного класса. Обучаемым и преподавателю нужен только браузер. Интернет для занятий не нужен: языковая модель и распознавание речи работают на сервере.

!tiles server | Сервер | Веб-приложение, база данных, телефонная станция, языковая модель.;; headset | Рабочие места | Браузер и гарнитура. Отдельный IP-телефон — по желанию.;; phone | Телефония | Учебные номера 201–220, звонки только внутри тренажёра.;; disk | Резервные копии | Ежедневно, в зашифрованном виде.

| Часть | Что делает |
| --- | --- |
| Сайт (Frontend) | страницы кабинетов и рабочего места, единый адрес для браузеров |
| Сервер приложения (Backend) | занятия, карточки, оценки, учётные записи |
| База данных (PostgreSQL) | все учебные данные |
| Голосовой модуль (Voice) | распознавание и синтез речи собеседников |
| Телефонная станция (Asterisk) | учебные номера, звонки из браузера и с IP-телефонов |
| Языковая модель (Ollama) | собеседники, новые карточки, рекомендации |
| Резервное копирование | ежедневные зашифрованные копии базы и файлов |

### Требования к серверу

- процессор от 6 ядер, оперативная память от 32 ГБ, диск от 100 ГБ;
- видеокарта не обязательна, с ней ответы собеседников и разбор ИИ быстрее;
- Linux (Ubuntu 22.04 и новее) или Windows 10/11, Docker с Compose;
- Python 3.11 и новее для служебных скриптов.

## Установка {#install}

1. Скопируйте папку тренажёра на сервер.
2. Подготовьте настройки. Скрипт создаст файл `.env.docker` со случайными паролями служб и телефонов:

   `python deploy/prepare.py`

3. Загрузите модели речи и языковую модель (один раз, около 6 ГБ):

   `python tools/fetch_models.py` и `python tools/fetch_llm.py`

4. Соберите и запустите:

   `python deploy/manage.py build`, затем `python deploy/manage.py up`

5. Проверьте: `python deploy/manage.py status` — все службы в состоянии «healthy».

Откройте адрес сервера в браузере. При первом запуске появится экран «Первый запуск»: создайте администратора, пароль не короче 12 символов.

!note Важно | Файл `.env.docker` содержит пароли служб и телефонов. Храните его копию отдельно от сервера и никому не пересылайте открыто.

### Демонстрационные данные

Чтобы сразу получить преподавателя, двух обучаемых, группу и занятия:

`python tools/seed_demo.py --base-url https://АДРЕС --admin ЛОГИН --admin-password ПАРОЛЬ`

Скрипт можно запускать повторно, дубликатов он не создаёт.

## Учётные записи {#users}

Войдите администратором. Откроется список пользователей.

!fig admin_portal | Пользователи | 

1. Заполните логин, отображаемое имя, роль и пароль. Нажмите «Создать пользователя».
2. Роль можно сменить в списке под пользователем.
3. «Закрыть доступ» блокирует вход, история и результаты сохраняются.
4. Внизу свёрнут блок «Дополнительно: политика доступа»: срок сессии, блокировка после ошибок входа, обязательный двухфакторный вход по ролям, срок хранения журнала.

Роли: **обучающийся** — рабочее место ДДС; **преподаватель** — группы, занятия, оценки; **администратор** — пользователи и технический кабинет.

Если забыт пароль администратора, выполните на сервере:

`docker compose --env-file .env.docker exec backend python reset_admin.py --username tech.admin`

Новый пароль будет показан один раз.

## Технический кабинет {#operations}

Ссылка «Технический кабинет» открывает состояние тренажёра.

!fig admin_operations | Состояние учебного контура | 1: общее состояние; 2: службы и их проверки; 3: раздел «Дополнительно»

На странице сверху вниз:

- **Требуют внимания** — сообщения о сбоях и перегрузке. После устранения их можно скрыть.
- **Службы** — каждая служба с отметкой «Исправна» или причиной сбоя. Службу можно остановить, запустить и перезапустить.
- **Резервное копирование** — включение ежедневной копии и её время; список копий и кнопка «Создать копию».
- **Журнал событий** — что происходило с тренажёром. Ссылка «Журнал безопасности и архив действий» вверху — входы, смены ролей, действия администраторов.

Редкие настройки свёрнуты в раздел **«Дополнительно»** внизу страницы:

- **настройки телефонии, базы данных и ресурсов** — адрес телефонной станции, разрешённые учебные номера, лимит одновременных звонков, память и процессор служб, профиль языковой модели и устройство (процессор или видеокарта). «Применить с перезапуском служб» — только когда нет занятий;
- установка подготовленного обновления, импорт и экспорт настроек;
- метрики сервера, очередь операций, системные журналы служб;
- выгрузка безопасной конфигурации без паролей.

## IP-телефония {#phones}

Каждый обучаемый в голосовом занятии разговаривает со своего учебного номера. Номера 201–220 и их пароли создаются при установке, они записаны в `.env.docker` в строке `SIP_ACCOUNTS_JSON`. Преподаватель закрепляет номер за обучаемым кнопкой «Настроить IP-телефоны» в занятии. Звонки идут только к учебным собеседникам, во внешнюю сеть не выходят.

### IP-телефон MicroSIP — основной способ на рабочих местах класса

На каждом рабочем месте устанавливается MicroSIP (подойдёт и другой SIP-телефон или аппаратный IP-телефон). Настройки учётной записи:

| Поле | Значение |
| --- | --- |
| Сервер (домен) | адрес сервера тренажёра |
| Порт и транспорт | 5061, TLS (в защищённом режиме); 5060, UDP — в простом режиме `--plain` |
| Шифрование звука | SRTP обязательно (в защищённом режиме) |
| Логин и ID авторизации | учебный номер, например 201 |
| Пароль | пароль этого номера из `SIP_ACCOUNTS_JSON` |
| Кодеки | PCMU, PCMA |

Для Windows-рабочих мест есть готовая настройка MicroSIP: `python deploy/configure_microsip.py --extension 201` (номер — для этого рабочего места). Для обучаемого подготовьте короткую карточку подключения: адрес сервера, номер и пароль телефона. Пароль телефона и пароль входа на сайт разные.

!note Важно | Каждый телефон — свой номер. Два устройства на одном номере перехватывают звонки друг у друга.

### Виртуальный телефон на сайте

Второй основной способ: ничего устанавливать не нужно, удобно для удалённой проверки. Обучаемый нажимает зелёный кружок с трубкой рядом с часами на рабочем месте, разрешает доступ к микрофону и выбирает гарнитуру. Логин и пароль браузер получает сам.

Что проверить администратору:

- сайт открыт по защищённому адресу (https), иначе браузер не даст доступ к микрофону;
- на рабочих местах подключены гарнитуры;
- номер 100 — эхо-тест: обучаемый слышит свой голос, значит звук в порядке.

### Запасной режим — текст

Если на рабочем месте нет гарнитуры, обучаемый в окне разговора выбирает «Текстом (без гарнитуры)». Проверки те же. Преподаватель может запретить текст в сценарии — тогда разговор возможен только голосом.

## Языковая модель {#model}

Модель работает на сервере через Ollama. Она ведёт разговоры собеседников, составляет новые карточки и пишет рекомендации. Оценка действий от модели не зависит: если модель недоступна, занятие идёт, собеседники отвечают по фактам сценария.

- Профиль модели и устройство выбираются в техническом кабинете: «Быстрая — для слабого сервера» или стандартная.
- Без видеокарты разбор ИИ после карточки занимает 3–5 минут и считается в фоне. Обучаемый тем временем берёт следующую карточку. Пока кто-то в классе говорит по телефону, разбор ждёт, чтобы не замедлять разговор.
- Карточки ИИ готовит заранее, запас — до 50 штук. Подготовка ждёт 10 минут без разговоров, а разбор ИИ прерывается, если начался звонок, и продолжается позже: процессор отдаётся разговору.
- Собеседники отвечают в среднем примерно за 3 секунды без видеокарты и примерно за 0,4 секунды с видеокартой. Модель всегда держится в памяти; при наборе номера роль собеседника готовится заранее, пока «идут гудки».

## Резервные копии {#backup}

Копии делаются автоматически раз в сутки и по кнопке в техническом кабинете. Каждая копия зашифрована и содержит базу данных и учебные файлы. Копии лежат на сервере в `deploy/backups`.

- Ключ шифрования хранится в `deploy/private/backup.env`. **Без него копию не восстановить** — сохраните ключ отдельно.
- Регулярно переносите копии на другой носитель.
- Копию базы вручную: `python deploy/manage.py backup-db`.

## Обновление и перезапуск {#update}

1. Завершите занятия.
2. Сделайте резервную копию.
3. Замените файлы тренажёра новой версией (`.env.docker` и папку `deploy/private` не трогайте).
4. `python deploy/manage.py build`, затем `python deploy/manage.py up`. Изменения базы применяются сами.

Остановить тренажёр: `python deploy/manage.py stop`. Данные при этом сохраняются.

!note Важно | Не используйте `docker compose down -v`: эта команда удаляет базу данных.

## Неисправности {#problems}

| Что случилось | Что сделать |
| --- | --- |
| Сайт не открывается | `python deploy/manage.py status`; запустите `up`, если службы остановлены |
| Браузер предупреждает о сертификате | установите на рабочие места корневой сертификат тренажёра `deploy/tls/ca/ca.cert.pem` |
| Нет звука в браузере | сайт должен открываться по https; проверьте гарнитуру и эхо-тест 100 |
| IP-телефон не регистрируется | сверьте номер, пароль, порт и транспорт; номер должен быть в списке разрешённых |
| «ИИ готовит для вас новую карточку» долго | проверьте службу модели в техническом кабинете; при перегрузке выберите быстрый профиль |
| Разбор ИИ «не удалось» | сервер был перегружен; обучаемый может нажать «Повторить ИИ-разбор» |
| Процессор загружен более чем на 90% | нормально во время подготовки карточек; если постоянно — уменьшите число одновременных звонков |
| Забыт пароль администратора | `reset_admin.py`, см. раздел «Учётные записи» |
