# Совместимость браузеров и мобильная вёрстка

Проверка выполнена 15 сентября 2026 года прогоном автономных браузерных тестов
в двух движках. Это не декларация: тесты открывают реальные страницы проекта с
перехваченным HTTP и проверяют поведение, а не только загрузку.

## Движки

ТЗ называет Chrome, Firefox и Яндекс.Браузер. Chrome и Яндекс.Браузер построены
на Chromium, поэтому проверяются одним движком; Firefox проверяется отдельно как
независимый Gecko.

| Движок | Версия | Результат |
| --- | --- | --- |
| Chromium (Chrome, Яндекс.Браузер) | Playwright 1.54 bundled | 8 из 8 сценариев |
| Firefox (Gecko) | 155.0 | 8 из 8 сценариев |

Покрытые сценарии: АРМ-112 (редактирование, сохранение, статусы служб,
телефонограммы, связи карточек, печать, журнал и фильтры), оценка и статистика,
генерация сценариев ИИ, занятие группы, живой просмотр занятия, карта,
методические материалы, учебные билеты.

Что **не** проверено: WebKit/Safari (не входит в требования и не установлен),
реальные сборки Chrome и Яндекс.Браузера вместо Chromium от Playwright,
прежние версии браузеров, работа с включёнными расширениями и корпоративными
политиками. Совпадение движка — сильный, но не абсолютный аргумент: сборки
Яндекс.Браузера могут отличаться настройками по умолчанию.

## Запуск

```powershell
npm install --no-save playwright
npx playwright install firefox     # chromium ставится вместе с пакетом

# один сценарий
node frontend/test_tickets_browser.cjs
$env:BROWSER_ENGINE='firefox'; node frontend/test_tickets_browser.cjs
```

Движок выбирается переменной `BROWSER_ENGINE` (`chromium` по умолчанию).
Тесты не поднимают Backend, базу, модель и не выходят в сеть: весь HTTP
перехватывается, статические файлы читаются с диска.

## Мобильная вёрстка

ТЗ требует удобства и в десктопной, и в мобильной версии. Три сценария —
АРМ-112, оценка и статистика, учебные билеты — в конце переключаются на ширину
400 px и падают, если у документа появляется горизонтальная прокрутка. Это
защищает от самой заметной поломки на телефоне; оценку удобства она не заменяет.

При этой проверке найдена и устранена реальная проблема рабочего места: панель
вкладок резервировала 105 px под оранжевую кнопку «создать новую карточку»,
которая свисает поверх неё, и рабочее место становилось на 33 px шире экрана.
На узких экранах кнопка теперь встаёт в поток, а строка состояния и панель
вкладок переносятся. Десктопный вид не изменился: правило действует только в
`@media(max-width:760px)`.

Снимок мобильного вида сохраняется в `tmp/arm-mobile.png` при каждом прогоне
ARM-сценария.

Планшеты и другие устройства с горизонтальной ориентацией используют десктопную
вёрстку, как и предусмотрено ТЗ.
