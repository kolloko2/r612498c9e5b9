# Локальная языковая модель: профили и замеры

Дата измерения: 16 сентября 2026 года. Хост: AMD Ryzen 5 5600 (6 ядер), Ollama
0.34.1, модель считалась процессором. Требования к серверу в ТЗ заданы диапазоном
и без видеокарты, а постановщик задачи на Q&A подтвердил: «только локально,
приоритет на локалку».

## Профили

Профиль выбирает администратор в техническом кабинете; это обычная настройка,
применяемая тем же обслуживанием, что и параметры SIP или PostgreSQL.

| Профиль | Модель | Назначение |
| --- | --- | --- |
| Без модели | — | занятия идут, генерация сценариев недоступна |
| Стандартная (CPU) | qwen3:4b | рекомендуемый профиль без видеокарты |
| Ускоренная | qwen3:8b | когда видеокарта есть |

Модель обслуживает локальный Ollama на хосте: `LLM_PROFILE` выбирает профиль,
`OLLAMA_URL` указывает адрес (по умолчанию `http://host.docker.internal:11434`).
Ключей и внешних сервисов в этой схеме нет.

## Замеры

| Задача | Стандартная (4b) |
| --- | ---: |
| Генерация сценария с эталоном | 6,1–6,3 с |
| Реплика дежурного при докладе | 0,5–0,7 с |
| Разбор текста карточки | 1,6–2,1 с |
| Десять одновременных реплик | 8,3 с на все, максимум 6,6 с |

Генерация возвращает полный сценарий и черновик эталона на 2–4 критерия.
Разбор текста карточки прошёл проверку шесть раз из шести.

Проверялся и профиль на модели 1.7b. Он генерировал сценарии за три секунды, но
не выдерживал требование дословных цитат в разборе карточки: цитаты оказывались
пересказаны, и разбор отклонялся целиком. Выигрыш в три секунды на задачах,
которые преподаватель запускает заранее, не стоит неполного функционала, поэтому
профиль убран. Роль страховки на слабом железе выполняет профиль «Без модели»,
где занятие целиком идёт на детерминированном ядре.

## Три исправления, без которых модель не работала

**Таймаут 35 секунд.** Локальная модель на процессоре выдаёт единицы токенов в
секунду, и генерация сценария законно занимает минуты. Для Ollama лимит поднят до
`LLM_TIMEOUT_SECONDS` (300 с по умолчанию); облачный провайдер сохраняет прежний
короткий лимит.

**Выгрузка модели между запросами.** Ollama по умолчанию выгружает веса через
несколько минут простоя, и следующий запрос платил около десяти секунд за
загрузку. Добавлен `keep_alive` (30 минут, настраивается `OLLAMA_KEEP_ALIVE`).

**Рассуждения вместо ответа.** Модели семейства qwen3 начинают ответ с «Хорошо,
мне нужно…», и это не отключается ни параметром `think: false`, ни директивой
`/no_think` — проверено, обе не помогают. Ответ упирался в лимит токенов прямо
посреди размышлений и не разбирался.

Решение — принуждение формата на стороне провайдера. Там, где ожидается JSON,
передаётся **JSON Schema**, а не просто «верни JSON»: без схемы модель охотно
возвращает валидный JSON, который повторяет присланные ей данные вместо ответа —
именно так и произошло с разбором карточки. Там, где нужна произносимая реплика,
`llm.reply` просит объект с единственным полем `reply` по схеме, и рассуждения
физически не помещаются в ответ. Разбор карточки после этого проходил проверку
шесть раз из шести вместо двух из пяти.

## Границы

Замеры сделаны на одной машине при свободном процессоре; параллельная нагрузка
(например, запущенная игра) занижает их в разы, и такие цифры непригодны. На
сервере заказчика замер нужно повторить.

Видеокарта в этих замерах не участвовала: `ollama ps` показывал 98 % CPU. Причина
не установлена — во время проверки карта была занята другим приложением.
Профиль «Ускоренная» поэтому не измерен и остаётся расчётным.

Качество сгенерированных сценариев здесь не оценивалось — проверялось только то,
что ответ разбирается, содержит обязательные поля и проходит проверки проекта.
Методическую пригодность сценария подтверждает преподаватель при валидации.
